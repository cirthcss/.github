# Support

The public issue tracker of the relevant repository is the primary support and
feedback channel for Cirth projects.

Before opening an issue:

1. Read the repository documentation and contribution guide.
2. Search open and closed issues for the same behavior.
3. Reduce bugs to the smallest reproducible example you can provide.
4. Remove private data, credentials, and production-only details.

For Cirth framework questions and reports, use
[`cirthcss/cirth/issues`](https://github.com/cirthcss/cirth/issues). Security
reports must follow [the security policy](SECURITY.md) and must not be posted
publicly.

Support is provided on a best-effort basis. Maintainers may redirect broad
implementation consulting, environment-specific debugging, or questions owned
by an upstream dependency.
