# Contributing to Cirth projects

Thank you for contributing to a Cirth organization repository.

Repository-specific contribution instructions take precedence over this file.
If a repository does not provide its own guide, use this baseline:

1. Search existing and closed issues before opening a new one.
2. Open an issue before substantial API changes or broad refactors.
3. Keep each pull request focused on one clear outcome.
4. Follow the repository's existing style and test conventions.
5. Add or update tests and documentation when behavior changes.
6. Run the documented checks locally before requesting review.
7. Call out breaking changes, compatibility concerns, and follow-up work.

Be concise but include enough context for another contributor to reproduce the
problem and evaluate the tradeoffs. Participation is subject to the
[Community Code of Conduct](CODE_OF_CONDUCT.md).
