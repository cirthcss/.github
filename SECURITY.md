# Security Policy

## Supported projects

Security fixes are considered for actively maintained Cirth repositories and
the latest published release. Older releases may require upgrading to receive a
fix.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include exploit
details in a public discussion.

Use the affected repository's **Security** tab and its private vulnerability
reporting channel when available. Include:

- the affected repository and version or commit;
- the impact and realistic attack scenario;
- reproduction steps or a minimal proof of concept;
- any suggested mitigation;
- whether the issue has been disclosed elsewhere.

If private vulnerability reporting is not available, contact the organization
owner through [their GitHub profile](https://github.com/ricpastori) to arrange a
private reporting channel before sharing technical details.

Maintainers will acknowledge actionable reports, investigate impact, coordinate
a fix and disclosure, and credit reporters who wish to be credited. Response
times are best effort; Cirth is currently maintained by a small team.

## Scope

Reports about the security of GitHub, npm, browsers, CDNs, or unrelated
dependencies should be sent to the responsible upstream project. Cirth accepts
reports when its code, published artifacts, documentation, or release process
creates or materially worsens the issue.
